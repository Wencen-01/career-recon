# 06 站：我的 Agent

## 1. 04 站的专家提示词和这次学的 Agent Skill 是什么关系？

04 站的提示词是"一次性的口头交代"——贴进对话框，用完就散，下次要用得重新复制粘贴。这次学的 Agent Skill，是把同样性质的"专家人设+知识索引+工作方式"正式变成一个存进仓库、随时能被召唤、还能带工具/脚本的"常驻专家档案"。

具体来说，不只是"保留"，还有"结构化"——Skill 有固定的格式要求（YAML frontmatter 的 `name`+`description`，加上正文的具体指令），这个格式让 Claude 能按需分层加载（三级渐进式披露），不用每次都把整段提示词塞进上下文。而且不只是"我们自己用"，还能被资源文件武装起来——参考官方文档 pdf-processing 的例子，Skill 可以带额外的 markdown 文件和可执行脚本，如果之后把 Performance Attribution 做成 Skill，理论上也可以配一个自动算配置/选股/交互效应的计算脚本。

**如果之后把 Performance Attribution 做好一个专家，可以把它封装成一个 skill，把配置文件保留在库里**——这是这个关系最直接的应用。

## 2. 装好工具后，第一件让你觉得"这东西真不一样"的具体事情是什么？

老实说，操作过程中主观感受上跟平时用 Chat 模式差不多，没有特别强烈的"完全不一样"的瞬间。

但客观上确实不同——Code 模式今天真的在硬盘上创建和修改了文件（`tmp/claude-code-desktop-ui-guide.md`），这是 Chat 模式做不到的，只是这个差异体现在"权限和产出物"上，没有直接反映在使用时的主观感受上。具体发生过的事：给它一张界面截图，它真实创建了一个文件；发现文档里两处推测性描述不准确后，主动联网核实、自己动手改了文件、附上真实来源链接；召唤 `/summarize` 时，按照一套从没交代过的固定格式产出摘要，这个格式提前写死在 SKILL.md 里。

## 3. 现在还有哪些开关/概念没搞明白，只是照着做了一遍？

目前最大的困惑是"不知道自己不知道什么"——具体列几个有印象但没真正搞懂的点：

- **Cowork 模式**：只读过官方定义（"面向知识工作者的自主 Agent"），跟 Code 模式的实际操作区别没有实操验证过
- **worktree**：只在选定工作文件夹、还未进入具体对话的过渡界面里出现过一次，进入实际对话之后就不再显示，容易被忽略；后来了解到这是 git 本身的功能——允许在同一仓库旁开出独立文件夹处于不同分支、互不干扰并行工作，但还没有实际用过
- **权限模式里的 Manual 和 Plan 两档**：全程只用了 Auto，Manual 和 Plan 具体长什么样、什么场景下该切换，没试过
- **Model 切换到 Opus 或 Haiku 的具体触发时机**：全程用的默认 Sonnet 5，什么情况该手动切模型不清楚
- **亲手写一个新的 SKILL.md 文件**：目前只看过别人写好的（summarize），还没有自己从零写过一个完整的 Skill 文件
